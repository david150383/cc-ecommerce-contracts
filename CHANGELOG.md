# Changelog

All releases follow [VERSIONING.md](VERSIONING.md).

## v1.2.0 — 2026-10-15

Cancelling a paid order (refund, then return the stock). Additions only:

- order-service: `OrderCancellationRequested` v1 event (a CONFIRMED/PROCESSING order is now
  CANCELLATION_PENDING; consumed by the saga)
- inventory-service: `InventoryReturnRequested` v1 command (put a CONFIRMED reservation's stock back on
  hand) and its answer, the `InventoryReturned` v1 event

## v1.1.0 — 2026-10-15

- payment-service: `Payment.status` and `Payment.provider` are published as enums (they were plain
  strings, so the contract promised less than the API returns). Narrowing a response: compatible
  (minor). Found by the frontend's compile-time contract check.

## v1.0.0 — 2026-10-15

First release: the contracts as they run today, extracted from the service repositories.

- 25 message schemas (JSON Schema 2020-12) with examples, owned per the ownership rules; ONE shared
  envelope (it had been copied into six repositories, identical except for `$id`)
- 7 OpenAPI documents (code-first: generated by each service and drift-tested there)
- Generated AsyncAPI 3.0 document and ownership matrix
- Fix found by the new checks: `OrderStatusTransitionRequested` goes to `order-commands.fifo` (the schema
  still said `order-commands` from before the queue became FIFO)
